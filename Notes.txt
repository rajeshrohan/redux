Redux Toolkit : 
RTK stands for Redux Toolkit.
created to simplify Redux development and eliminate common boilerplate patterns.
It is maintained by the Redux core team.

----------------------------------------------------------------
installation : 
npm i @reduxjs/toolkit
npm i redux-logger 
npm i react-redux

syntax: 
import { configureStore } from "@reduxjs/toolkit";          
import { Provider } from "react-redux";             // binding 
import { createLogger } from "redux-logger";        // logger 

const logger = createLogger();
const store = configureStore({
  reducer: {
    account: accountReducer,
    bonus: bonusReducer,
    reward: rewardReducer,
  },
  middleware: (getDefaultMiddleware) => getDefaultMiddleware().concat(logger),
});

Note :
<Provider store={store}>    -> correct 
<App store={store}>         -> wrong

----------------------------------------------------------------
createAction()              -> used to create action. 
createReducer()             -> used to create reducer logic.
syntax :
const initialState = { points: 15 };                                // state 
export const increment = createAction("reward/increment");          // action 

const rewardReducer = createReducer(initialState, (builder) => {    // reducer 
  builder
    .addCase(increment, (state, action) => {
      state.points++;
    })
});

params1 = initialState
params2 = Callback with builder object.

extraReducers:
Problem 1 : 
when you want to change the state of another another reducer fn , 
from current reducer fn. 
syntax : 
export const bonusSlice = createSlice({
  name: "bonus",
  initialState,
  reducers: {
    increment: (state) => {
      state.points += 1;
    },
  },
  extraReducers: (builder) => {
    builder.addCase(incrementBonusByCondition, (state, action) => {
      if (action.payload >= 100) state.points++;
    });
  },
});

Note : used for async functions also.

Q. Why extraReducers is used?
Use it when:
1. The action belongs to another slice
2. Multiple slices need to respond to the same action
3. Handling async actions like createAsyncThunk

Example scenario:
accountSlice → deposit money
bonusSlice → give reward points, on higher amount deposit.
So deposit action triggers bonus logic.

----------------------------------------------------------------
SUMMARY : 

createAction →
creates action creators that return standard Redux actions `{ type, payload }`,
useful when actions must be reused across multiple reducers or slices.

createReducer → 
defines a reducer function using a simpler syntax with Immer, 
allowing direct state mutation (state.value++) while internally producing immutable updates.

createSlice → 
combines (initial state, reducers, and auto-generated action creators) in a single structure,
reducing boilerplate for Redux logic.

extraReducers → 
allows a slice to respond to actions defined outside the slice, 
such as actions from other slices or lifecycle actions from async thunks.

combineSlices → 
automatically combines multiple slice reducers into a single root reducer, 
similar to combineReducers but designed for Redux Toolkit slices.

configureStore → 
creates the Redux store with sensible defaults, 
automatically setting up Redux DevTools, thunk middleware, and combining reducers.

createAsyncThunk → 
simplifies asynchronous logic (API calls) by generating 
`pending`, `fulfilled`, and `rejected` action types and handling promise lifecycles.

createEntityAdapter → 
provides utilities for managing normalized collections of data (like users, posts) 
with built-in reducers for add, update, remove, and selectors.

createSelector → 
creates memoized selectors that compute derived data from the store and 
only recompute when the input state changes.
